# 数据标注指南

> 先搞清楚你要的是哪种"标注" —— 这两件事完全不同，工具和工作量差 10 倍。

| | **A. 评估标注**（你现在需要） | **B. 训练标注**（想换掉 COCO 主体模型才需要） |
|---|---|---|
| 标什么 | 给照片打**结论标签**（保留/复核/淘汰、清晰/模糊…） | 给目标画**边界框**（框住人/狗/商品…） |
| 工具 | **Excel / WPS 就行** | X-AnyLabeling / labelImg |
| 工作量 | 100 张 ≈ **15 分钟** | 每类 ≥300 框 ≈ **2-3 天** |
| 产出 | `data/labels.csv` | `datasets/mydata/`（YOLO txt + data.yaml） |
| 用途 | 算准确率、校准阈值（**答辩的量化评估那一页**） | 训练自己的 `.pt` → 导出 ONNX 替换模型 |
| 本项目 | ✅ **必须做**（`tools/evaluate.py` 直接吃这个） | 🟡 可选，属于"未来扩展" |

**结论**：课程设计阶段，做 A 就够，而且性价比极高。B 只在"你的主体都是 COCO 类别外的东西"（比如全是商品/零件）时才值得。

# 一、A 类：评估标注（推荐先做这个）

## 1.1 目录准备

```bat
cd photo-selector
mkdir data\imgs
:: 把要评估的照片放进 data\imgs\ （60~100 张，覆盖各种情况）
python tools\evaluate.py --init      :: 生成 data\labels.csv 模板
```

## 1.2 标注表怎么填

`data/labels.csv`（UTF-8，Excel 直接打开）：

| 列 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `文件名` | ✅ | `IMG_001.jpg` | 必须和 `data/imgs/` 里的文件名**完全一致** |
| `人工建议` | ✅ | `建议保留` / `建议复核` / `建议淘汰` | **你的主观判断，是评估的主指标** |
| `人工清晰度` | 选填 | `清晰` / `模糊` | 填了才会评估清晰度模块 |
| `人工曝光` | 选填 | `正常` / `过曝` / `欠曝` | |
| `人工色彩` | 选填 | `正常` / `平淡` / `杂乱` | |
| `人工主体` | 选填 | `有` / `无` | 画面里有没有明显主体 |
| `备注` | 选填 | 任意 | 比如"逆光""主观难判" |

**填写技巧（省一半时间）**：

1. **只填 `人工建议` 也能跑** —— 先只标这一列，100 张 15 分钟搞定
2. **先标"建议淘汰"** —— 有硬伤（糊了/过曝/全黑）的一眼就能定，先筛出这批最快
3. **拿不准就不填** —— 空白的行评估脚本会自动跳过，比瞎标更准
4. **一个人从头标到尾** —— 两个人的主观标准不一致，会让准确率莫名其妙变低
5. **别边看系统结果边标** —— 会不自觉地"迎合"结果，评估就失真了（这是最常见的错误）

## 1.3 照片从哪来

| 来源 | 说明 |
|---|---|
| 自己手机相册 | 最真实，直接覆盖日常场景（推荐） |
| 故意造坏图 | 用手机连拍+走动造模糊，暗光造欠曝，对着灯造过曝 |
| 网上公开图 | 注意版权，课程设计内部使用一般没问题 |

**尽量覆盖 6 类**：清晰正常 / 模糊 / 过曝 / 欠曝 / 色彩平淡 / 有明确主体，每类 10~15 张。

## 1.4 跑评估

```bat
python tools\evaluate.py                    :: 用 data/labels.csv + data/imgs/
python tools\evaluate.py --scan             :: 额外做阈值扫描（给答辩用）
python tools\evaluate.py --labels 路径 --images 路径
```

输出示例：

```
样本数 60（跳过空白 2）  总体准确率 81.7%
混淆矩阵（行=人工，列=系统）
              建议保留  建议复核  建议淘汰
  建议保留        18        4        0
  建议复核         3       21        2
  建议淘汰         0        2       10

分类指标
  建议保留  precision 85.7%  recall 81.8%  F1 83.7%
  建议复核  precision 77.8%  recall 80.8%  F1 79.3%
  建议淘汰  precision 83.3%  recall 83.3%  F1 83.3%

单模块准确率（有真值的项）
  清晰度  91.7%   (55/60)
  曝光    88.3%
```

报告会存到 `output/eval_report_*.md`，**直接可以贴进答辩 PPT 的"测试与评估"页**。

## 1.5 阈值扫描（答辩加分）

`--scan` 会对 `blur_threshold` 从 10 扫到 120，打印每个阈值的清晰度判定准确率，帮你找到最优值：

```
blur_threshold  清晰度准确率
      20.0          85.0%
      30.0          88.3%
      40.0          91.7%   ← 最优（当前默认值）
      60.0          90.0%
     100.0          86.7%
```

**这就把"阈值不是拍脑袋定的"变成可验证的结论** —— 老师问"阈值怎么来的"，你直接指这张表。

# 二、B 类：训练标注（想做再往下看）

## 2.1 什么时候才需要

只有这三种情况：
1. 你的主体是 **COCO 80 类之外**的东西（商品、零件、菜品、特定仪器…）
2. 你只要少数几个类别，希望**精度更高、模型更小**
3. 报告里想写"我们自己训练了模型"（加分项）

否则**别做** —— 现成的 YOLOv8n 已经够用，省下的时间做评估更值。

## 2.2 工具选择

| 工具 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| **X-AnyLabeling** ⭐ | 国内维护、界面现代、支持 SAM 半自动（点一下就出框）、能导出 YOLO | 需要 Python 3.8-3.11 | **首选** |
| labelImg | 老牌、轻量、教程最多 | 界面老、无半自动 | 够用 |
| Label Studio | 功能全、多人协作 | 重、要起服务 | 团队分工才用 |
| Roboflow | 在线、免装 | 免费额度有限、数据要上传 | 有网且量小可以 |

安装（X-AnyLabeling，一行）：

```bat
pip install anylabeling
anylabeling
```

## 2.3 标注格式（YOLO）

每张图对应一个 `.txt`，每行一个目标：

```
<class_id> <x_center> <y_center> <width> <height>
0 0.523 0.412 0.310 0.488
```

- 所有坐标都**归一化到 0~1**
- `class_id` 从 0 开始，和 `data.yaml` 里的 `names` 对应
- 没有目标的图 → 建一个**空 txt 文件**（重要，否则会被当负样本漏掉）

## 2.4 目录结构

```
datasets/mydata/
├── images/train/   train_001.jpg ...
├── images/val/     val_001.jpg ...
├── labels/train/   train_001.txt ...
├── labels/val/     val_001.txt ...
└── data.yaml
```

`data.yaml`：

```yaml
path: C:/Users/CHI/Desktop/sdt/photo-selector/datasets/mydata
train: images/train
val: images/val
names:
  0: person
  1: pet
```

## 2.5 工作量与配比

| 项 | 建议 |
|---|---|
| 每类图片数 | ≥ 150 张（模型越小小，数据要越多） |
| 训练/验证比例 | 8 : 2 |
| 标框时间 | 简单目标 10~20 秒/框；一张图 3 个目标 ≈ 1 分钟 |
| 最小可行 | 3 类 × 150 张 ≈ **1.5~2 天**（业余时间） |

## 2.6 省时间大招：半自动预标注

先用现成模型框一遍，人工只做"改错"，能省 70% 时间：

```bat
:: 在 yolo 环境里（这个脚本用的是 ultralytics 的自动标注）
yolo mode=segment ...  :: 或直接用下面这个
```

ultralytics 自带 `auto_annotate`（Python）：

```python
from ultralytics.data.annotator import auto_annotate
auto_annotate(data="data/imgs", det_model="weights/yolov8n.pt", output_dir="data/auto_labels")
```

生成的框再导入 X-AnyLabeling 人工修正。**注意**：预标注只对 COCO 已有类别有效，类别外目标还得手画。

## 2.7 训练 + 替换模型

```bat
:: 1) 训练（在 yolo 环境里）
yolo train model=weights/yolov8n.pt data=datasets/mydata/data.yaml epochs=100 imgsz=640 batch=16

:: 2) 导出 ONNX（注意用项目里的 opencv 也能读的 opset）
yolo export model=runs/detect/train/weights/best.pt format=onnx imgsz=640 opset=12

:: 3) 替换模型文件 + 改配置
copy runs\detect\train\weights\best.onnx ..\photo-selector\models\mydata.onnx
```

再改 `config.py`：

```python
"subject_model_path": "models/mydata.onnx",
```

### ⚠️ 一个必须改的坑

`modules/subject.py:28` 里的 `COCO_NAMES` 是**写死的 80 类**。换成自己的模型后，
类别索引含义变了，必须对应修改：

```python
MY_NAMES = ["person", "pet"]   # 和你 data.yaml 的 names 顺序一致
```

否则界面上显示的主体类别会是错的（比如你的"商品"被显示成"toaster"），
但**分数和通过与否不受影响**（那些只看框的大小）。

不过 `tests/test_subject.py` 里有断言 `top_class == "dog"`，换模型后这个测试会红，
记得一起改掉。

# 三、质检：怎么知道自己标得对不对

| 做法 | 说明 | 成本 |
|---|---|---|
| **自己隔天重标 10 张** | 和第一次对比，一致率 <90% 说明标准不稳 | 5 分钟 |
| **两人交叉标 20 张** | 算一致率，报告里可以写"标注一致性 92%" | 30 分钟 |
| **只信"明显"的样本** | 拿不准的标"存疑"列，评估时排除 | 0 |
| **避免迎合系统** | 先标完再跑系统，别来回看 | 0 |

**答辩可以用的话术**：

> 我们的评估集由我们自己采集标注，共 N 张，覆盖 6 类典型场景。
> 为避免主观偏差，标注时不参考系统输出；其中 20 张做了两人交叉标注，
> 一致性 92%。

# 四、一句话总结

- **评估标注（A）**：Excel 填 `data/labels.csv` → `python tools\evaluate.py` → 准确率/混淆矩阵 → 贴进答辩 PPT

- 无论哪条路，**先小规模跑通（20 张）再上量**，别一上来标 300 张

# 五、用本项目自带工具链做训练标注（推荐直接照这个做）

> 适用场景：你的照片主体是 COCO 80 类**认不出来**的东西（商品、乐器、菜品、特定物件、特定宠物…），
> 系统一直报"未检测到主体"→ 建议复核/淘汰，把好照片误判了。

整条链路只有 5 步，全部有现成脚本/bat：

```
建数据集 → 放照片 → 画框 → 体检 → 训练 → 改一行配置
```

## 5.1 第一步：建数据集（一条命令）

先想清楚你要识别哪几类，**类别名用英文小写**（顺序就是 class_id）：

```bat
:: 例：你要认"人、宠物、商品"三类
python tools\init_dataset.py --names "person,pet,goods"
```

它会自动生成：

```
datasets/mydata/
├── classes.txt          ← 类别表（一行一个）
├── data.yaml            ← 训练配置（自动生成，别手改）
├── images/train/        ← 把照片放这里
├── images/val/          ← 之后自动抽 20%
├── labels/train/        ← 画完的框存这里
└── labels/val/
```

> `datasets/` 已在 `.gitignore` 里，不会进仓库。

## 5.2 第二步：放照片

把手机照片直接拷进 `datasets/mydata/images/train/`。

**数量建议**：每类 **150~300 张**能出可用模型；先弄 **20~30 张把流程跑通**，再补量。

覆盖要杂一点：不同角度、远近、光照、有没有遮挡、背景杂乱/干净都要有。
**反例也要**：明显不含目标的照片放几张（标成空文件），能减少误检。

## 5.3 第三步：画框（双击 `数据标注.bat`）

工具已经装好在 yolo 环境里（**X-AnyLabeling 0.4.43**），这个 bat 会自动：

- 用你的 `classes.txt` 当类别列表（不用手动配置类别）
- 标注直接存到 `labels/train/`
- 打开 `images/train/` 里的图

**快捷键**：

| 键 | 作用 |
|---|---|
| `W` | 画一个框（拖拽），然后选类别 |
| `D` / `A` | 下一张 / 上一张 |
| `Ctrl + S` | 保存（`--autosave` 已开，通常自动存） |
| 滚轮 | 缩放（小目标先放大再框） |

**画框要点**：

1. **框要紧贴目标边缘**，别留大片空白，也别把目标切掉一块
2. **一张图里有几个目标就画几个框**，漏标比多标更伤模型
3. **画面里没有目标**：建议什么都不画（工具可能不生成空文件，`check_dataset` 会提示，
   可以手动建一个同名空 `.txt`，或者干脆把这类图移出数据集）
4. **拿不准的模糊框别硬画** —— 宁可少一张图
5. 一类只用一个类别名，**别一会儿 `pet` 一会儿 `pets`**

> 如果后续想装 SAM 半自动（点一下就自动出框），X-AnyLabeling 界面里可以下载模型；
> 但简单目标手动框也很快（一个框 5~10 秒），不值得为它折腾网络。

## 5.4 第四步：整理数据（双击 `整理数据.bat`）

> ⚠️ 关键一步：标注工具存的是**它自己的 `.json`**（绝对像素坐标），
> YOLO 训练只认**归一化的 `.txt`**。这个 bat 会自动调 `tools/json2yolo.py` 转换，
> 你不用手动在 GUI 里点导出。

它会依次做：

1. **JSON → YOLO txt**（`tools/json2yolo.py`）：矩形/多边形统一取外接框，坐标归一化到 0~1，
   不在 `classes.txt` 里的标签会被跳过并列出（告诉你哪个标签没认出来、几个框）
2. **划分验证集**：val 为空时自动挪 20% 过去（已分过就跳过）
3. **数据体检**（`tools/check_dataset.py`）

也可以手动分开跑：

```bat
python tools\json2yolo.py
python tools\init_dataset.py --split 0.2
python tools\check_dataset.py
```

输出 `READY. Next: double click the train bat.` 才能进下一步。

体检会查这些，有问题直接告诉你在哪个文件第几行：

| 检查项 | 报什么 |
|---|---|
| 类别一致性 | `data.yaml` 和 `classes.txt` 对不对得上 |
| 标注格式 | 每行必须 5 个字段 |
| `class_id` 越界 | 比如只有 3 类却写了 `class_id=9` |
| 坐标越界 | 归一化坐标必须在 0~1（超出说明画框或导出出错） |
| 宽高为 0 | 手滑画成一条线 |
| 孤儿标注 | 有 txt 没图片（图片被删/改名了） |
| 未标注图片 | 有图片没 txt（还没画，或忘了建空文件） |
| 类别框数 | **某类一个框都没有会直接报错**（该类训练时被忽略）；少于 30 个会提示 |

输出 `✅ 数据集检查通过，可以训练了` 才能进下一步。

## 5.5 第五步：训练（双击 `训练模型.bat`）

它会调用 `..\yolo\.venv` 里的 torch + ultralytics（**项目自己的轻量环境不带 torch**），
默认从官方 `yolov8n.pt` 做迁移学习：

```bat
训练模型.bat                          :: 默认 100 epochs, imgsz 640
训练模型.bat --epochs 30              :: 先短跑验证流程
训练模型.bat --epochs 200 --imgsz 800 :: 认真训练
```

**时间参考（很关键）**：

| 环境 | 100 epochs × 200 张图 |
|---|---|
| 你的 RTX 5060（GPU） | 约 10~20 分钟 |
| 纯 CPU | **几小时**（先用 `--epochs 30` 验证） |

> 训练完会打印 mAP 等指标，曲线图在 `runs/train/mydata/`，**答辩可以直接用**。

## 5.6 第六步：把模型换进系统（只改一行）

训练脚本会自动做两件事：

1. 导出 `models/mydata.onnx`（opset 12，`cv2.dnn` 能读）
2. 写 `models/mydata.names.txt`（类别名）—— **系统会自动读它，不用改代码**

你只需要改 `config.py` 第 79 行左右：

```python
"subject_model_path": "models/mydata.onnx",   # 原来是 models/yolov8n.onnx
```

然后：

```bat
双击 跑测试.bat
```

⚠️ **唯一需要手动改的地方**：`tests/test_subject.py` 里断言了 `top_class == "dog"`
（因为原来用 COCO 模型）。换成你自己的模型后这条会红，把断言改成你的某个类别名，
或者换成一张带该类目标的样例图。

改完后旧模型想换回来，只改 `subject_model_path` 就行，**代码零改动**。

## 5.7 常见坑

| 现象 | 原因 / 解决 |
|---|---|
| 启动报 `Failed to save config: C:\Users\xxx\.anylabelingrc` 然后 `FileNotFoundError` | 这台机器**不允许在用户目录根下新建文件**（`.streamlit` 当初也是这个原因）。`数据标注.bat` 已自动把 `HOME/USERPROFILE` 重定向到项目里的 `.toolconfig/`，正常双击不会有这个问题；如果你绕过 bat 直接运行 `anylabeling.exe`，需要自己设这两个环境变量 |
| 训练报 `no labels found` | `--split` 前标注没跟着走，或标签目录路径不对。跑 `check_dataset.py` 看 |
| 训练后模型什么都认不出 | 数据太少（<50 张/类）或类别标错。至少 150 张/类 |
| 界面显示的主体类别是错的 | 忘了 `.names.txt`，或者它的顺序和 `classes.txt` 不一致 |
| 训练很慢 | CPU 训练。先 `--epochs 30` 验证流程，或用 GPU |
| 模型认不出新类别 | 训练数据里没有那个类别，或该类框太少（<30） |
| `anylabeling` 打不开 | 用 `数据标注.bat`（它指向 yolo 环境的 exe）；直接 `pip install` 到别的环境会缺 Qt |

## 5.8 一条命令回顾

```bat

:: 放照片到 datasets\mydata\images\train\
双击 数据标注.bat
python tools\init_dataset.py --split 0.2
python tools\check_dataset.py
双击 训练模型.bat --epochs 30
:: 改 config.py -> models/mydata.onnx
双击 跑测试.bat
```
